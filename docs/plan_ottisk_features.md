# План: перенос фич «Оттиска» в pulse_qt (снап, СК, планы, экспорт замеров)

Статус: черновик, 2026-11-04.

Источники: разбор **Ottisk.exe v1.3.2** (Electron 33 + Three.js): встроенная справка
(`appdist/help/*.html`), все русские UI-строки и код бандла (`entry-*.js`), electron-модули.
Карта pulse_qt: `docs/plan_hierarchy.md`-стиль; ключевые файлы описаны ниже по ходу.

## Что в Pulse уже есть (не переносим)

- **Замеры в 3D**: `measure.py` — `dist / height / plane / poly`, `evaluate()/label()/details()`,
  отметки от нуля `elevation()`; подписи — `Viewport.set_labels`.
- **Сечение**: `section.py` — `slice/clip`, толщина `thick`, основы `z/x/y/plane`, довороты a/b,
  `vtk_planes()`. Рамка, сетка.
- **DXF**: `drawing.write_dxf` (ezdxf, R2010, мм, слои contour/grid/openings/text) — для листа чертежа.
- **Цвет**: `display.py MODES = ('auto','solid','height','range')` — по высоте уже есть.
- **Навигация**: ортовид `CloudView.set_parallel`, `ViewCubeWidget` (widgets.py), `fit/look_at`.
- **Undo** (только чистка): `Session.erase_undo`. **Настройки панелей**: `state()/restore()` + QSettings.
- **Пиккинг**: свой ray casting `CloudView.pick_point(x, y, tol_px=7, names=...)` — ближайшая
  точка к курсору в экранной зоне, учёт сечения.

## Фаза 1 — ядро замеров

### Ф1. CAD-снап (osnap)

**У Оттиска** (из кода бандла): режимы — битовая маска `snapModes`,
по умолчанию `ClosestPoint | Vertex | NearestProjection`:

| бит | Название | Что подхватывает |
|-----|----------|------------------|
| ClosestPoint | «Точка на выделенном» | вершина облака/сплата под курсором |
| Vertex | «Вершина / конец» | вершины уже нарисованных меток |
| NearestProjection | «Проекция 3D» | свободная точка на видимой поверхности |
| Midpoint | «Середина / центр» | середины рёбер меток, центры кругов |
| Extend | «Удлинить / укоротить» | продолжение сегмента метки |
| Intersection | «Пересечение» | пересечение рёбер меток (в разработке) |

Приоритет: **вершина метки > точка облака**; при включённом снапе клик мимо
кандидатов ничего не ставит; прицел подсвечивается, когда снап валиден. Клавиша B —
вкл/выкл снапа целиком. Клик в «пустоту» при снапе не ставит точку.

**В Pulse**: точка ставится в 3D по-разному в зависимости от инструмента; замеры
(«Общее» → замеры) используют `view.pick_point`. Расширение:

- `CloudView.snap_pick(x, y, measures, modes, tol_px=7)` → `(p, kind)`:
  собирает кандидатов по режимам: точки скана (есть `pick_point`), вершины и
  середины рёбер `session.measures`, центры окружностей плоскостей (`fit`-круги —
  `fits.element_wire`), проекция на плоскость сечения как fallback для
  NearestProjection; сортировка: сначала candidates меток, затем облако; каждая
  группа — по экранной близости к курсору. Учитывать видимость (глаз) и сечение
  (как `pick_point`).
- Подсветка прицела: маркер в слое `ren_top` (там уже живёт подсветка), цвет —
  акцент при валидном снапе, серый — нет.
- UI: чек-кнопки режимов в панели замеров (секция «Привязка»), состояние в
  `state()/restore()`; клавиша B в `_shortcuts()` — только в режиме замеров.

**Файлы**: `pulse_qt/cloud_view.py`, `measure.py` (кандидаты), `pulse_qt/main_window.py`
(режим замеров), панель замеров.
**Тесты** (`tests/test_snap.py`, без окна): синтетическая комната
(`tests/test_registration.py:scan()`); кандидаты вершина/середина/центр;
приоритет метки над облаком при равной экранной близости; отсечение по `thick`.

### Ф2. Undo замеров

**У Оттиска**: Ctrl+Z, стек до 10 шагов, только действия с измерениями.

**В Pulse**: по образцу `erase_undo`:

- `Session.measure_undo` — `collections.deque(maxlen=10)`;
  перед каждой мутацией `measures` (добавить, удалить, переименовать, правка
  координат, коммит драга) → `measure_undo.append(copy.deepcopy(self.measures))`.
- `Session.undo_measure()` — снимает последний снимок и заменяет им `measures`;
  хук Ctrl+Z в `MainWindow._shortcuts()`
  активен только пока открыт режим замеров (не мешать undo чистки).

**Файлы**: `scan_session.py`, `main_window.py`.
**Тесты**: add/undo/redo-состояния в `tests/test_session.py`.

### Ф3. Числовой ввод координат

**У Оттиска**: у выбранного замера ✎ раскрывает «Название/Примечание» и координаты:
Точка — XYZ; Расстояние — Начало/Конец XYZ; Круг — Центр XYZ + Радиус.
Коммит по Enter или потере фокуса; пересчёт всех величин сразу; ввод всегда
в **мировых метрах** (не в СК) — явно написано в справке.

**В Pulse**: панель замера уже показывает значение/детали (`measure.details`).
Добавить у выбранного замера редактируемые `KV`-поля координат вершин
(общая система) + `OptNum` радиуса у кругов; ввод → `m['pts'][i] = ...` →
перерисовать замер (`Viewport.set_labels` + линии) и обновить значение.
Плюс поля **«Название»** и **«Примечание»** (новые поля `name`, `note` в dict
замера, `.get()` — обратная совместимость старых проектов; попадают в CSV Ф6).

**Файлы**: панель замеров (`control_panel.py` / inspector), `scan_session.py`
(сериализация `name/note` в `_project_dict`).
**Тесты**: правка координат → `evaluate()` пересчитан; roundtrip name/note в проекте.

### Ф4. H-отметка в подписи

**У Оттиска**: клавиша H / кнопка «H↕» у точки — вписывает «H=+12.34 м» второй
строкой в подпись (всегда со знаком; высота в базисе активной СК либо по
вертикали сцены).

**В Pulse**: у `height`-замера отметка уже считается (`elevation()`); добавить
флаг `m['with_h']` → в `label()` вторая строка «H=±X.XX м» у точечных замеров
(height/точка poly из 1 точки). Клавиша H на выбранном замере.

**Файлы**: `measure.py`, `main_window.py` (хоткей).
**Тесты**: формат строки со знаком.

## Фаза 2 — СК и экспорт

### Ф5. Пользовательская СК (север)

**У Оттиска**: создание в 2 клика — точка 0, затем точка направления оси X
(высота второй точки игнорируется, ось строго горизонтальна); Z = вертикаль,
Y = Z×X (правая тройка). Поле «Азимут севера» (°) — доворот вокруг вертикали.
Активная СК переключает: координаты меток (подпись «(СК)»), гизмо/ViewCube,
экспорт CSV/DXF. Конвенция подписей **X=восток, Y=север, Z=высота**; в коде есть
скрытый переключатель «CAD/Геодезия» (X↔Y в заголовках CSV: `X(север)/Y(восток)/H`)
— у нас вывести как опцию с самого начала. Наклонную СК двумя кликами нельзя —
только последующим поворотом.

**В Pulse**: вертикаль уже нормирована `level` (Z вверх, после `level_pose`/
`level_project`). Модель:

```json
"cs": {"origin": [x, y, z], "yaw_deg": 0.0, "geodetic": true}
```

- Базис: `E = [cos yaw, sin yaw, 0]`, `N = [-sin yaw, cos yaw, 0]`, `U = [0,0,1]`
  (yaw=0 → E=+X, N=+Y). `world_from_cs(p)` / `cs_from_world(p)` — в `scan_session.py`.
- `Session.cs = None | dict`; создание: инструмент «СК» (лента «Общее») —
  клик 1 (origin), клик 2 (направление X: горизонтальная проекция луча
  `ray_plane_z`); защита от вертикали второго клика (просьба кликнуть ещё).
- Редактирование: поля origin XYZ + yaw в панели; сброс (вернуться к мировым).
- Отображение: у подписей замеров координаты в СК + пометка; ViewCube/оси —
  опция «оси = СК» (подставить базис в `set_camera`-базис); стрелка «N» на
  кубе/гизмо — как у Оттиска.
- `zero_z` и `elevation()` не трогаются — СК влияет только на координаты и экспорт.
- Совместимость: проект без `cs` — как сейчас.

**Файлы**: `scan_session.py` (модель, конверсии, сериализация), инструмент СК
(`main_window.py`, панель), `measure.py` (подпись в СК), `widgets.py` (N-стрелка).
**Тесты** (`tests/test_cs.py`): построение по 2 точкам (включая наклонный
второй клик), yaw-повороты, `cs_from_world ∘ world_from_cs = id`, CSV в СК (Ф6).

### Ф6. Экспорт замеров в CSV

**У Оттиска**: строка на каждую вершину каждого замера;
`ID;Название;Тип;Вершина;X;Y;Z;Значение;Единицы;Примечание`; в геодезическом
режиме заголовки `X(север);Y(восток);H`; координаты в базисе активной СК,
иначе мировые.

**В Pulse**: новый `measure_export.py`:

```python
def csv_rows(session) -> list[list[str]]   # по вершинам замеров
def write_csv(session, path)               # ';' + utf-8-sig (Excel-friendly)
```

- Типы — наши названия («Отрезок», «Высота», «Плоскость», «Ломаная», «Площадь»…),
  значение — `measure.evaluate()`, единицы «м» (° для углов plane).
- Координаты: `cs_from_world` если `session.cs`, иначе мировые; заголовки по
  `cs['geodetic']`.
- UI: кнопка «Экспорт» в панели замеров → `QFileDialog` (monkeypatch-дружественно:
  через `MainWindow`-обёртку, как остальные экспорты).

**Тесты** (`tests/test_export_measures.py`): парсинг csv, число строк = число
вершин, координаты в СК.

### Ф7. Экспорт замеров в DXF (3D)

**У Оттиска**: рукописный DXF R12 (AC1009), `$INSUNITS=6` (метры), слои с цветами ACI:

| Слой | ACI | Содержимое |
|------|-----|------------|
| IZM_POINT | 2 | POINT |
| IZM_DIST | 1 | LINE |
| IZM_LINE | 3 | POLYLINE (VERTEX/SEQEND) |
| IZM_AREA | 5 | POLYLINE замкнутая |
| IZM_CIRCLE | 4 | CIRCLE |
| IZM_TEXT | 7 | TEXT (значения/имена) |

`$EXTMIN/$EXTMAX` по габариту. План-привязанные замеры — на отдельном слое плана
(актуально с Ф8).

**В Pulse**: ezdxf уже в зависимостях — писать через него (`ezdxf.new('R2010')`,
`doc.units = 6`/`$INSUNITS=6`, **метры**, в отличие от листов чертежей в мм —
указать в диалоге). `measure_export.write_dxf(session, path)`: те же имена слоёв
`IZM_*` и ACI-цвета (совместимость с Оттиском при открытии их файлов и наоборот);
текстовые подписи — имя + значение. Координаты в СК если задана; ориентация
X→DXF-X (восток), Y→DXF-Y (север) — вид сверху в CAD совпадает с видом сверху
при севере вверх.

**Тесты**: `ezdxf.readfile` обратно: слои, число сущностей, z-координаты
(паттерн `test_drawing.py`).

## Фаза 3 — планы

### Ф8. Сохранённые планы (несколько сечений)

**У Оттиска**: список «Планы»: имя «План N (H=…)», H редактируемая (у
горизонтальных), глаз, переименование, двойной клик — reopen для дорисовки,
удаление плана **не удаляет** его замеры (отвязывает). Замер знает свой план
(бейдж «Привязано к плану», кнопка «Отвязать»). Пока план активен — на сцене
только его замеры; лист планов восстанавливается при следующем открытии модели,
но планы не активируются сами.

**В Pulse**: сейчас `Session.section` — один dict. Перенос:

```json
"plans": [
  {"id": "plan1", "name": "1 этаж", "visible": true,
   "state": {"mode": "slice", "base": "z", "n0": [...], "a": 0, "b": 0,
             "c": 1.2, "thick": 0.10, "flip": false}}
]
```

- `Session.plans` + `active_plan`; `section` остаётся **видом** (что сейчас
  показывается) — активация плана копирует его `state` в `section` (или `section`
  становится ссылкой — решить по коду `keep_mask/vtk_planes`).
- Замер: `m['plan'] = plan_id` (опционально). При активном плане — фильтр замеров
  в `Viewport` (только этого плана) и автопривязка новых замеров к нему;
  «Завершить план» — вернуть обзор.
- Замеры одного плана рисуются на своей базовой плоскости — при reopen можно
  драгом/дорисовкой продолжать (зависит от Ф1/Ф3).
- **Навигация по планам** (как у Оттиска; активное сечение одно — поверх него
  могут работать боксы Ф15):
  активация плана — камера плавно летит в вид вдоль нормали (горизонтальный план —
  строго сверху) + включается ортопроекция (`set_parallel`, полёт камеры — общий
  механизм с Ф14); поле H в строке плана — сдвиг `section['c']` по высоте
  («прокрутка этажей»); хоткеи предыдущий/следующий план (PgUp/PgDn в контексте
  режима сечения); миникарта «Вид сверху» — отдельный виджет Qt, контент —
  `drawing.band_points` + `skeleton_paths` текущего среза (уже есть), обновление
  после пересчёта среза.
- UI: секция «Планы» в панели сечения (`control_panel.py`) или в дереве
  (у нас деревья органичнее — группа «Планы» в `ProjectTree`, контекстное меню:
  активировать/переименовать/глаз/удалить/DXF Ф9).
- Совместимость: старый проект с активным `section` → один план в списке.

**Тесты** (`tests/test_plans.py`): roundtrip планов, отвязка замеров при
удалении плана, фильтр видимости.

### Ф9. Экспорт плана в плоский 2D-DXF

**У Оттиска**: кнопка DXF в строке плана: точки проецируются на плоскость,
полилинии с единой высотной отметкой — «плоский» чертёж этажа.

**В Pulse**: `measure_export.write_plan_dxf(session, plan, path)`: замеры плана
в 2D-базисе плана (u,v по `section.axes`), z = отметка плана у всех. Опция
«+ контур среза»: скелетные контуры уже умеет `drawing.build(session, st)`
(полоса среза → цепочки) — дёшево добавить их отдельным слоем `CONTOUR`.

**Тесты**: 2D-DXF читается, все z равны отметке, полилинии замкнуты.

### Ф15. Боксы отсечения и композиция сечений (изоляция комнаты / перекрытия)

**Задача**: работать только с одной комнатой (спрятать всё вокруг) или только
с перекрытием. У Оттиска это «Боксы отсечения» (help/clip-box.html), но у них
режет один объём за раз и бокс нельзя совместить с активной плоскостью «Плана».
У нас делаем сильнее: **активная область = сечение (slice/clip) ∩ объединение
включённых боксов**.

- Перекрытие решается уже сейчас: сечение `slice` по Z с толщиной (полоса
  вокруг отметки); сохранённое перекрытие = план (Ф8). Комната — бокс.

**Модель данных**:

```json
"clip_boxes": [
  {"id": "box1", "name": "Комната 101", "on": true, "visible": true,
   "center": [x, y, z], "size": [dx, dy, dz], "yaw_deg": 0.0}
]
```

- Бокс — осе-упорядоченный (yaw вокруг вертикали); хранится в общей системе
  и двигается вместе с level/zero, как `section` (не в системе скана).
- **Семантика нескольких боксов** (осознанное улучшение против Оттиска):
  показываются точки внутри любого включённого бокса (объединение — работа
  с несколькими комнатами сразу); включённое сечение AND-ится поверх
  (перекрытие внутри комнаты).

**Вычисления**:

- `clip.py` (новый): `box_planes(box) -> 6 плоскостей (n, c)`,
  `inside_mask(pts, box)`, `combined_mask(pts, session)` — маска сечения
  (`section.keep_mask`) AND (объединение боксов, если включён хоть один).
- `cloud_view.py`: `set_section` принимает список плоскостей (VTK держит
  несколько clipping planes: 6 бокса + 1–2 сечения, лимит GPU обычно ≥ 8);
  каркас бокса — `set_lines` (12 рёбер).
- `drawing.build`: опционально подмешать combined_mask (план одной комнаты) —
  после Ф8.

**UI**:

- Кнопка «Бокс» в ленте «Общее» (рядом с сечением): размер из поля, клик по
  модели — центр бокса (как у Оттиска); «Бокс по проекту» — по габариту облака.
- Список боксов — группа в дереве (рядом с «Планами» Ф8): чек = режет,
  глаз = каркас, контекстное меню: переименовать, центр по клику, удалить.
- Панель бокса: поля center/size/yaw + «повернуть по стенам» (манхэттенский
  снап — логика `align_plan_to_walls` по нормалям элементов).
- Драг граней/рёбер как у Оттиска — опционально позже по паттерну `_ring_drag`;
  MVP = числовой ввод + клик-центр.

**Совместимость**: проект без `clip_boxes` — как сейчас. **Отличие от чистки**:
боксы — неразрушающий вид (точки не удаляются), `erase`/`drop` остаются

**Файлы**: `clip.py` (новый), `scan_session.py`, `cloud_view.py`,
